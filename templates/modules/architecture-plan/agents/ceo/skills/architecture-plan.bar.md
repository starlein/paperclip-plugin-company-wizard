## Architecture Plan — Done Bar (CEO Primary)

The CEO primary owns an implementable architecture for the agreed, bounded planning scope, not a placeholder pending an absent specialist.

**Done:**
- `docs/ARCHITECTURE.md` covers the scoped system overview, components and responsibilities, data flows, API boundaries, deployment model, and key decisions with rationale. Use an appropriate level of detail; identify justified non-applicable sections, assumptions, risks, and unresolved decisions explicitly rather than inventing technical certainty.
- The plan supports incremental implementation. Necessary follow-ups name an actual present owner and concrete scope. If expertise is unavailable, persist a governed hiring or input request rather than assigning an absent engineer or a literal capability selector.
- Required unresolved decisions remain on a structured waiting path: dependency `blockedByIssueIds`, or a saved pending interaction plus `in_review` for human input. Separate optional implementation follow-ups from prerequisites to accepting this plan.

**Not done:**
- An empty placeholder, unexplained omissions, or a plan without actionable boundaries and rationale.
- Declaring required unresolved architecture decisions complete merely because a follow-up was created.
